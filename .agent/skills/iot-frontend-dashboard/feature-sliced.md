# Feature-Sliced Architecture

> Every feature has a folder. Every folder has a purpose. If a component has no home, you have not understood the domain.

---

## Top-Level Layout

```
src/
├── app/                        # Next.js App Router (pages only)
│   ├── dashboard/              # Protected dashboard routes
│   │   ├── vehicles/           # Vehicle pages
│   │   │   └── page.tsx        # Thin shell: imports from features/
│   │   ├── devices/            # Device pages
│   │   ├── alerts/             # Alert pages
│   │   ├── geofences/          # Geofence pages
│   │   ├── trips/              # Trip pages
│   │   ├── customers/          # Customer pages
│   │   ├── firmware/           # Firmware pages
│   │   ├── drivers/            # Driver pages
│   │   ├── fuel/               # Fuel analytics pages
│   │   └── settings/           # Settings pages
│   ├── login/                  # Public auth pages
│   └── layout.tsx              # Root layout (providers, fonts)
│
├── features/                   # Feature modules (business logic)
│   ├── vehicles/               # Vehicle feature
│   │   ├── components/         # Feature-specific components
│   │   ├── hooks/              # Feature-specific hooks
│   │   ├── types/              # Feature-specific types
│   │   └── utils/              # Feature-specific utilities
│   ├── devices/
│   ├── alerts/
│   ├── geofences/
│   ├── trips/
│   ├── customers/
│   ├── firmware/
│   ├── drivers/
│   ├── fuel-analytics/
│   └── {new-feature}/
│
├── components/                 # Shared UI components (used across features)
│   ├── ui/                     # shadcn/ui generated components
│   ├── layout/                 # Shell: sidebar, header, page-container
│   └── shared/                 # Reusable composed components
│
├── hooks/                      # Global hooks (cross-cutting only)
│   ├── use-auth.ts             # Authentication hook
│   ├── use-socket.ts           # Socket.IO connection hook
│   └── use-media-query.ts      # Viewport detection
│
├── lib/                        # Utilities and clients
│   ├── api/                    # API client functions (per domain)
│   ├── api-client.ts           # Axios/fetch wrapper with auth headers
│   └── utils.ts                # Generic utilities (cn, formatDate)
│
├── stores/                     # Zustand stores (global state)
│   ├── auth-store.ts           # Token + user in memory
│   └── ui-store.ts             # Sidebar state, preferences
│
├── config/                     # Configuration
│   └── nav-config.ts           # Sidebar navigation structure
│
└── types/                      # Global TypeScript types
    └── api/                    # API response/request types
```

## Feature Folder Internals

```
features/{name}/
├── components/                 # UI components for this feature
│   ├── {name}-table.tsx        # Data table (list view)
│   ├── {name}-form.tsx         # Create/edit form
│   ├── {name}-details.tsx      # Detail view
│   ├── {name}-toolbar.tsx      # Table toolbar (search, filters)
│   └── {name}-stats.tsx        # Stats cards or charts
│
├── hooks/                      # Feature-specific hooks
│   ├── use-{name}.ts           # TanStack Query hook (single item)
│   ├── use-{name}-list.ts      # TanStack Query hook (list + pagination)
│   └── use-{name}-mutations.ts # Create, update, delete mutations
│
├── types/                      # Feature-specific types
│   └── {name}.types.ts         # Interfaces, enums, zod schemas
│
└── utils/                      # Feature-specific utilities
    └── {name}.utils.ts         # Formatters, calculators, mappers
```

## Where Does a New Component Belong?

```
New component needed
│
├── Is it used by only ONE feature?
│   ├── YES --> features/{feature}/components/
│   └── NO  --> Continue below
│
├── Is it a shadcn/ui primitive (Button, Dialog, Input)?
│   ├── YES --> components/ui/ (generated by shadcn CLI)
│   └── NO  --> Continue below
│
├── Is it part of the app shell (sidebar, header, breadcrumbs)?
│   ├── YES --> components/layout/
│   └── NO  --> Continue below
│
├── Is it a composed component used by 2+ features?
│   ├── YES --> components/shared/
│   └── NO  --> It probably belongs in a feature folder
│
└── Is it a page-level component?
    ├── YES --> app/dashboard/{feature}/page.tsx (thin import shell)
    └── NO  --> Re-evaluate. Most things belong in features/
```

## Where Does a New Hook Belong?

```
New hook needed
│
├── Is it specific to one feature's data or UI?
│   ├── YES --> features/{feature}/hooks/
│   └── NO  --> Continue below
│
├── Is it cross-cutting (auth, socket, media query)?
│   ├── YES --> hooks/ (global)
│   └── NO  --> Continue below
│
├── Is it a TanStack Query wrapper for an API?
│   ├── YES --> features/{feature}/hooks/ (always feature-specific)
│   └── NO  --> hooks/ (global) if truly generic
```

## When to Create a New Feature Module

| Signal | Decision |
|--------|----------|
| New backend domain with its own REST endpoints | New feature module |
| New page under /dashboard/{name} | New feature module |
| New data table with its own CRUD | New feature module |
| Extra component for existing feature | Extend existing feature |
| Shared utility (date formatting, cn helper) | `lib/` or `lib/utils.ts` |
| New API client function | `lib/api/{domain}.ts` |

## Page Component Pattern

```
app/dashboard/{feature}/page.tsx is a THIN SHELL:
│
├── Import the main component from features/
│   import { VehicleTable } from "@/features/vehicles/components/vehicle-table"
│
├── Wrap with page-level concerns only
│   ├── PageContainer (from components/layout/)
│   ├── Breadcrumbs
│   └── Page title
│
└── NO business logic in page.tsx
    ├── No API calls
    ├── No state management
    ├── No complex UI logic
    └── Just composition and layout
```

## Anti-Patterns

| Pattern | Problem | Fix |
|---------|---------|-----|
| Components at root `src/components/` for feature-specific UI | No feature isolation | Move to `features/{name}/components/` |
| Hooks in global `hooks/` for feature-specific data | Breaks feature boundaries | Move to `features/{name}/hooks/` |
| Business logic in `app/dashboard/*/page.tsx` | Page files should be thin shells | Extract to feature components and hooks |
| One giant `features/{name}/index.tsx` | No component separation | Split into focused component files |
| Importing from one feature into another | Feature coupling | Extract shared code to `components/shared/` or `lib/` |
| API types scattered across features | Duplication, drift | Centralize in `types/api/` |
